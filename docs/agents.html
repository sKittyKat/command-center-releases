Site agents

A site agent makes a change to one of your websites from a brief you write. It works on a copy, QA checks what it made, and nothing goes live until you choose Accept and merge.

Add your sites

For each website, add its GitHub repository in Settings › Claude › Agents (or the set-up's Your sites step) with a fine-grained token for that one repository, with Contents and Pull requests read and write. The token stays in your keychain; no agent ever holds it.

A run, start to finish

  1. Brief. Assign a project's work to an agent and write what you want. You see its budget ($5 to start) and confirm; it must fit within Claude's monthly cap.
  2. Work. Command Center hands the agent a copy of the site. The agent never touches GitHub itself: Command Center commits what it made, only to a branch of its own (cc/…).
  3. Questions. If the agent needs an answer, it reaches your agenda as a Reply; it waits for you even when other work runs on Auto.
  4. QA. Every change is checked before you see it (below). If it fails, the agent gets it back to fix, and you see the final round.
  5. Review. The finished work reaches Review with QA's results, what changed and its cost.
  6. Accept and merge. Merging is publishing, so it's always at least Approve. Only the exact commit QA passed is merged.

The QA gate

Seven checks, out of the agent's hands. Four are Command Center's own, judged from the built site opened in a hidden, sandboxed window, never from the agent's report:

  • The site builds with its own build command.
  • Works on phones and desktops: every changed page lays out without sideways scrolling at 390 and 1440 pixels wide.
  • No broken links or placeholder text on the changed pages.
  • Accessibility basics: alt text, labelled fields, headings in order, and enough text contrast (axe-core).

Three are graded by Claude:

  • Matches the brief, and nothing else changed.
  • Copy proofread: spelled right, grammatical, in the site's own voice.
  • Client summary written: two to four plain sentences for your client on what changed and why.

Where agents run

  • Managed Agents: in Anthropic's sandbox, through your API key.
  • Claude Code on this computer: with your Claude plan, in a folder of Command Center's own. It needs Git installed.

Choose in Settings › Claude › Agents. Either way the run's cost counts against Claude's monthly cap, and a run can't spend past its budget.

Staying in control

  • Stop a run any time from the Agents screen.
  • Review anyway looks at work QA didn't pass, if you want to.
  • The Assign agent tasks and Deploy or publish guardrails decide what needs your click; deploying is never Auto.
